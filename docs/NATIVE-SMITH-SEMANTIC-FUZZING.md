# Native Smith Semantic Fuzzing

This layer uses Zig 0.16's `std.testing.fuzz` and `std.testing.Smith` as the input-generation and coverage-guided mutation engine. It intentionally does not maintain a parallel genetic algorithm.

## Contract-aware generation

`src/smith_fuzz.zig` maps the existing `FunctionSpec` constraints to structured candidates:

- integers emphasize declared minima, maxima, and adjacent values, while still sampling the interior;
- strings emphasize minimum/maximum lengths and mutate their contents through Smith-generated bytes;
- booleans use the native value-generation API;
- string allocation is bounded to 256 bytes per field;
- generated inputs are checked against their declared constraints, and Smith-derived seeds exercise the canonical case generator.

## Run

```sh
zig build test
zig build test-fuzz
```

`test-fuzz` uses Zig's native bounded fuzz mode. The exact mutation/corpus/coverage behavior is owned by the Zig toolchain, not reimplemented here.

## Scope

This first adapter fuzzes the contract-aware input mapping and canonical test-case generator. It does not claim to execute business Actions: runtime execution, branch/trajectory feedback, invariant oracles, and crash triage require a separate isolated execution adapter. Such feedback can be added later without replacing Smith.

Generated payloads remain ephemeral. Do not connect this target to production side effects.
